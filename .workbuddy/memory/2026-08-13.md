# 2026-08-13

## 项目上下文（重要）
- 工作区 `oii_sticker`（双 i）= 基于 **Tauri 2 + Vue 3 + TS** 的桌面项目，目前是空模板（仅默认 `greet` 命令 + `tauri-plugin-opener`）。
- 源项目 `oi_sticker`（单 i，`E:\AAACodeProjectMy\oi_sticker`）= **Slint 1.17 + rusqlite + tokio** 跨平台桌面便签应用（多窗口 Markdown 便签、三模式 display/interact/edit、SQLite 持久化、pulldown-cmark 渲染、tokio 提醒调度、托盘、通知、Win32 任务栏隐藏）。
- 目标：把 `oi_sticker` 的**非 UI 逻辑**迁移集成进 `oii_sticker`（Tauri 2）。

## 本次产出
- 通过 4 个并行分析智能体完成详尽调研（架构/数据层/UI边界与设计意图/目标工程现状），其中数据层智能体首轮误读双 i 目录，已重跑单 i 目录纠正。
- 生成迁移方案：`E:\AAACodeProjectMy\oii_sticker\MIGRATION_PLAN.md`（极详尽，仅 plan 不含代码）。

## 关键结论 / 决策点
- Tauri 原生优先：窗口/托盘/通知/自启/透明 一律用 Tauri API，禁手搓 Win32 / tray-icon / notify-rust。
- 单一 tokio runtime（复用 `tauri::async_runtime`），不新建。
- `db/` `markdown/parser` `datetime/` `slash/` `commands` 纯逻辑整段保留；`render.rs`/`ui/*.slint`/`WindowSink` 丢弃。
- 最高风险：GPL v3 许可（源 GPL v3，衍生须同协议）、手搓 Win32 与 Tauri 冲突、逻辑嵌 Slint（自动滚动/双击/resize 需下沉为纯函数）、`remind_at` 格式不统一、capabilities 需扩展。
- 待用户确认：许可、前端形态、通知实现、display 语义、旧库兼容、非目标功能范围。

## 用户已确认决策（全部已决，第三轮收尾）
- 动画不迁移；前端完全 Vue 3 重设计；数据库迁移且仍用 SQLite；**许可沿用 GPL v3**；**通知用 tauri-plugin-notification（不保留 notify-rust）**；**Markdown 渲染完全用 Web 技术 markdown-it（Rust 移除 pulldown-cmark 的 Block 管线，仅留 list.rs + edit_* 纯文本变换）**。
- 所有阻塞项已关闭，方案 `MIGRATION_PLAN.md` 已达 v1.2，可进入编码阶段。
- 关键架构简化：因 Markdown 渲染移到前端 markdown-it，Rust 侧 `markdown/parser|inline|html|render` 全部丢弃，`pulldown-cmark` 依赖移除；todo 勾选源行映射改用 markdown-it token.map。

## 方向重大调整（第四轮）：改为全新重写，不再移植
- 用户判断：直接从零用 Tauri 2 + Vue 3 重写比移植 Slint 更简单快速。
- 新方案 `REWRITE_PLAN.md`（v1.0）取代 `MIGRATION_PLAN.md`：功能仿照 oi_sticker（作为需求规格），但技术栈与代码 100% 全新；不复用任何 Slint 代码。
- 架构要点：Tauri 多窗口（每便签=一个 WebviewWindow，label=`sticker-<id>`，前端按 label 分发渲染）；Rust 核心 + rusqlite + tauri-plugin-notification/autostart + markdown-it 前端渲染；沿用已确认决策（GPL v3 / Vue3 / 无动画 / SQLite / markdown-it）。
- 之前对 oi_sticker 的分析结论继续作为功能规格使用，无需重做分析。
- 旧 MIGRATION_PLAN.md 可归档/删除。

## 前端技术栈与工程规范补充（用户要求）
- 前端库：`pinia`(必选状态管理)、`vue-router`(窗口内视图)、`@vueuse/core`、`vuedraggable`(Vue3 next)、`dayjs`、`sass`(CSS 预处理，二选一建议 sass)；渲染用 `markdown-it`。不引入 pulldown-cmark。
- 工程规范（写入 REWRITE_PLAN §4.3）：Rust 大功能→文件夹、子功能→独立 .rs 文件；前端大功能→文件夹、页面/组件拆分避免单 .vue 文件过大（建议 ≤300-400 行）；**全程多用 v-model/defineModel 双向绑定**，pinia 为单一真相源。
- 多窗口模型：每个便签=一个 Tauri WebviewWindow（label=`sticker-<id>`），前端按窗口 label 分发渲染。
