# Todo 窗口功能完善设计

## 目标

完善独立 Todo 窗口的三个行为：

1. Todo 窗口默认置顶，并允许在系统设置中修改。
2. 一个根任务可以拥有任意数量的直接子任务，但子任务不能继续创建子任务。
3. 时间和重复预设按钮产生明确的选中状态；已选值显示在字段标题中，自定义按钮文字保持固定。

## 现状与边界

- Todo 窗口由 Rust 的 `open_todo_window_cmd` 创建，当前 `create_todo_win` 没有设置原生窗口置顶。
- Todo 子任务限制同时存在于 Rust 仓储和 Vue 列表：仓储拒绝第二个直接子任务，列表用 `find` 只渲染一个子任务。
- Todo 时间数据已通过 `TodoPatch` 保存为 ISO 字符串，重复规则已支持 `unit`、`interval` 和每周 `weekdays`。
- 重新打开窗口时不保存预设来源，因此有值的时间或重复规则统一显示为“自定义”选中状态。

## 设计

### 1. Todo 窗口置顶

新增 system config 键 `default_todo_always_on_top`，默认值为 `1`，描述为“Todo 窗口默认是否置顶”。

- 首次初始化数据库时写入该默认值。
- 对已存在的 v7 数据库增加 v7 → v8 迁移，使用 `INSERT OR IGNORE` 写入配置，不覆盖用户已有配置。
- 系统设置 Todo 页面增加复选框，读取和写入该配置。
- 新建 Todo 窗口和重新显示已存在的 Todo 窗口都读取当前配置并调用 `set_always_on_top`。
- 设置改变时，同步当前已打开的 Todo 窗口；之后新建或重新打开的窗口也使用新值。

窗口置顶设置失败不阻断 Todo 数据加载或窗口显示；Rust 侧记录警告，前端设置保存仍可完成。

### 2. 无限直接子任务

后端创建规则：

- `parent_id` 为空时创建根任务。
- `parent_id` 非空时，父任务必须存在、属于同一便签且自身没有 `parent_id`。
- 不再检查父任务是否已有子任务，因此直接子任务数量不设上限。

前端列表规则：

- 使用按 `parent_id` 分组的计算结果渲染所有根任务及其直接子任务。
- 每个直接子任务使用稳定的任务 id 作为 key，并保持缩进样式。
- 根任务在列表或详情中都可以发起“添加子任务”。
- 选中子任务时不显示“添加子任务”入口；后端规则作为第二层防线继续拒绝孙任务。

删除根任务时沿用 SQLite 外键级联删除其全部直接子任务。

### 3. 时间和重复交互

`TodoDetail` 按每个字段维护一个仅用于当前窗口交互的来源状态：预设按钮、`custom` 或空值。来源状态不写入数据库。

- 初次加载或切换任务时：字段有值则来源为 `custom`，无值则为空。
- 点击任一预设按钮：保存对应值，关闭弹层，并将该按钮设为蓝色。
- 自定义日期或重复选择器保存：保存值，关闭弹层，并将“自定义”按钮设为蓝色。
- 字段内按钮文字始终固定，不替换为已选日期或重复摘要。
- 清空功能不在本次范围内；仍可通过自定义选择器修改已有值。

标题摘要规则：

- 无值：`提醒时间`、`截至时间`、`设置任务重复`。
- 提醒时间：`提醒时间 - YYYY年M月D日 HH:mm`。
- 截至时间：`截至时间 - YYYY年M月D日 HH:mm`。
- 周期为周且存在星期：`设置任务重复 - 每 N 周的 周一、周二`，星期按周一到周日的顺序显示。
- 其他周期：`设置任务重复 - 每 N 天/周/月/年`。

其中“截至时间 - 今天”预设按产品示例写入下一自然日 `00:00`；其他已有 Todo 时间预设继续使用系统设置中的小时和星期配置。

## 组件与数据流

- `TodoWindow`：窗口生命周期、Todo store 编排、关闭与拖拽；继续通过 props/events 连接子组件。
- `TodoList`：只负责根任务和直接子任务的展示，接收 `items`、`selectedId`，发出选择、创建、勾选事件。
- `TodoDetail`：编辑任务文本、时间/重复选择来源状态和摘要，向上发出 `TodoPatch`。
- `TodoDatePicker`：只负责日期时间选择并 emit ISO 值。
- `RepeatPicker`：只负责周期、间隔和周几选择并 emit JSON 规则。
- `settings` store：读取和写入 system config；Todo 窗口原生置顶同步由 Rust 命令处理。

## 错误处理

- 创建非法孙任务或跨便签子任务时，后端返回现有错误；前端不提供该入口。
- Todo 窗口置顶 API 失败只记录日志，不影响窗口创建和 Todo 功能。
- 时间或重复规则 JSON 无法解析时显示无值摘要，不让详情组件渲染失败。

## 测试策略

按 TDD 依次添加失败测试并实现：

- Rust 仓储：同一父任务可创建两个及以上直接子任务；子任务作为 parent 仍失败；既有子任务高级字段限制和级联删除保持不变。
- Rust schema/命令：v7 → v8 写入默认 Todo 置顶配置且不覆盖已有值；打开或配置变更时应用窗口置顶状态。
- Vue `TodoList`：渲染同一根任务下的全部子任务，子任务没有添加入口。
- Vue `TodoDetail`：预设按钮保持固定文字并显示蓝色选中态；标题显示格式化日期和重复星期；切换任务时已有值恢复为自定义状态。
- 工程验证：运行相关 Vitest、完整 Vitest、`pnpm build`，并检查 Rust 测试（若本机 Rust 工具链可用）。

## 非目标

- 不改旧 Markdown `todo_items` 数据模型。
- 不允许子任务继承或单独设置提醒、截至时间和重复规则。
- 不新增任务排序、拖拽、删除按钮或跨窗口的预设来源持久化。
